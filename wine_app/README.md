# Подборка вин — демо-приложение к ДЗ-3

Streamlit-приложение для сомелье сервиса подписки на вина: по лабораторному анализу вина
логистическая регрессия оценивает вероятность того, что вино «хорошее» (оценка экспертов ≥ 7),
и решает, включать ли его в подборку. Модель в приложении **не обучается**: оно только загружает
файлы, сохранённые ноутбуком `HW3_MMDA.ipynb`.

| Файл | Что это |
| --- | --- |
| `app.py` | приложение |
| `model.joblib` | итоговый пайплайн `StandardScaler → LogisticRegression`, обученный на train |
| `config.json` | порог по умолчанию: 0.2432 (наибольшая precision при recall ≥ 0.7 на валидации) |
| `test.csv` | тестовая выборка (1950 вин, 12 признаков + `target`) |
| `requirements.txt` | точные версии библиотек |

## Запуск

Нужен **Python 3.11** (проверено на 3.11.6). Версии в `requirements.txt` менять не стоит:
`model.joblib` сохранён scikit-learn 1.9.1, и другая версия может не загрузить модель
или выдать предупреждение о несовместимости.

```bash
cd wine_app
python3.11 -m venv .venv
source .venv/bin/activate          # Windows: .venv\Scripts\activate
pip install -r requirements.txt
streamlit run app.py
```

Streamlit откроет приложение в браузере (по умолчанию http://localhost:8501).
Остановить сервер — Ctrl+C в терминале. Пути к файлам строятся от папки `app.py`,
поэтому запускать можно из любой директории: `streamlit run путь/к/wine_app/app.py`.

## Что есть в приложении

- **Сайдбар** — ползунок порога. По умолчанию порог берётся из `config.json`, кнопка возвращает его.
  Порог хранится в `st.session_state` и общий для всех вкладок.
- **Оценка одного вина** — 11 числовых полей (диапазон — минимум и максимум по `test.csv`,
  значение по умолчанию — медиана) и переключатель «белое / красное». Показывает вероятность
  и решение при текущем пороге.
- **Модельные метрики** — на тестовой выборке при текущем пороге: матрица ошибок, precision,
  recall, F1 (с изменением относительно порога из `config.json`), ROC- и PR-кривые с точкой
  текущего порога и пояснение для сомелье, что будет с подборкой при изменении порога.
- **Пакетное предсказание** — загрузка CSV, таблица с вероятностью и решением для каждого вина,
  скачивание результата. Если не хватает столбцов или есть нечисловые значения, приложение
  выводит понятную ошибку и не падает. Столбец `target` и другие лишние столбцы
  не используются при предсказании. Можно скачать пример файла.
- **Что выучила модель** — коэффициенты логистической регрессии после стандартизации,
  отсортированные, с подписями «за» и «против» хорошего вина.

## 4.5. Почему модель кэшируется через `st.cache_resource`, а таблицы — через `st.cache_data`

Streamlit выполняет `app.py` заново сверху вниз при каждом действии пользователя: при каждом
сдвиге ползунка или изменении поля.

- **`st.cache_resource`** — для «ресурсов»: глобальных объектов, которые создаются один раз и
  используются всеми сессиями и перезапусками (модели, соединения с базой). Декоратор хранит
  **один объект на весь сервер** и возвращает ссылку на него, без копирования и без сериализации.
  Модель только читается (`predict_proba` её не меняет), поэтому делить один экземпляр между
  пользователями безопасно. Копировать её при каждом вызове было бы дорого и бессмысленно.
  Если загружать модель через `st.cache_data`, Streamlit на каждом перезапуске заново
  десериализовал бы копию из кэша, т. е. делал бы почти ту же работу, что `joblib.load`.
- **`st.cache_data`** — для данных: `DataFrame`, массивов, результатов вычислений. Результат
  сериализуется, и **каждый вызов получает свою копию**. Если код одной сессии изменит таблицу
  (например, добавит столбец), кэш и другие пользователи этого не увидят. Ключ кэша — хеш
  аргументов. В `test_proba(_model, X)` модель передаётся с подчёркиванием, поэтому Streamlit её
  не хеширует, и ключ — только `X`. Вероятности на test считаются один раз, а при движении
  ползунка меняется только сравнение с порогом. Автотест проверяет, что `predict_proba`
  на тестовой выборке за несколько перезапусков вызывается один раз.

**Что будет, если вызвать `joblib.load` без декоратора.** Приложение будет работать, но при
**каждом** перезапуске скрипта (каждом движении ползунка, каждом вводе числа) модель будет
заново читаться с диска и десериализоваться, причём отдельно в каждой сессии: каждый
пользователь держит свою копию в памяти. Наша модель весит 2 КБ, и это незаметно, но для
реальных моделей размером в сотни мегабайт интерфейс начнёт тормозить при каждом движении
ползунка, а память будет расти с числом пользователей.

## Деплой на Streamlit Community Cloud

Ссылку на развёрнутое приложение автор добавляет в ноутбук сам после деплоя.

1. Создать репозиторий на GitHub (публичный или приватный) и положить в него папку `wine_app/`
   целиком: `app.py`, `model.joblib`, `config.json`, `test.csv`, `requirements.txt`, `README.md`.
   `model.joblib` и `test.csv` маленькие, Git LFS не нужен.
2. Войти на [share.streamlit.io](https://share.streamlit.io) через GitHub и нажать
   **Create app → Deploy a public app from GitHub**.
3. Указать репозиторий, ветку и **Main file path** `wine_app/app.py`.
   `requirements.txt` из папки с `app.py` Community Cloud найдёт сам.
4. В **Advanced settings** выбрать **Python 3.11**, чтобы версии из `requirements.txt` совпали
   с теми, на которых модель сохранена и проверена.
5. Нажать **Deploy**, дождаться сборки и открыть ссылку вида `https://<имя>.streamlit.app`.
   Проверить все четыре вкладки и движение ползунка.
